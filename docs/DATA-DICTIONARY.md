# 双写定义

event_id唯一，doc_id文本保留。side为source或index；版本正整数按Decimal比较并作为文本序列化。upsert要求JSON对象，delete忽略payload并产生墓碑。相同文档同端同版本不同内容全部隔离，存在未裁决冲突的主体不回落旧版本；同内容合并来源；较高版本覆盖低版本，迟到旧写不得覆盖墓碑。

双端最终版本、操作、文档分别核验。目标缺失、删除未确认、索引领先、陈旧索引、内容差异分开展示。source_time与visible_time带偏移；可见延迟按实际秒数。默认阈值120秒，等于阈值通过。已可见但超过阈值为延迟，尚无目标且等待时间超过阈值为缺失，等待中不冒充延迟。

对账expected=每文档应通过的1，reported=门禁通过1或未通过0，逐条保存visibility_state和gate原因，允许按文档复核。

## 孤存裁决

孤存文档指索引侧有记录、源端批次没有对应记录。缺记录本身不是撤稿证据，取值如下：

- `ORPHAN_WAITING`（门禁`等待`）：源端补齐水位尚未覆盖该索引事件、观察期未满、索引事件缺源时刻、源端存在被隔离记录，或本批没有任何源端记录。不能下架，也不得算延迟或内容差异。
- `ORPHAN_RETIRABLE`（门禁`可下架`）：源端补齐水位已覆盖该索引事件，且自水位起观察期已满（默认600秒，等于边界即满）。这是唯一可作为可下架结论的取值。
- `ORPHAN_SETTLED`（门禁`通过`）：索引侧本身已是删除墓碑，已撤内容已不可见，无需再等待。

水位来源：参数`source_watermark`（别名`source_complete_through`、`backfill_watermark`等）优先，否则取本批源端记录的最晚`source_time`；两者都没有时视为覆盖不明，一律等待。`as_of`默认`2026-11-16T10:10:00Z`，`orphan_grace_seconds`默认600。

每条孤存结论带`conclusion_id`（证据编号）与`conclusion_evidence`（索引事件、水位、观察期）。可见性重建生成结论，延迟门禁、双写对账、最终封存只读取并校验，不得各自改判；同一批次各阶段的`conclusion_digest`必须一致。

对账口径：只有`ORPHAN_SETTLED`（已消失）算门禁通过、对账无差异；`ORPHAN_RETIRABLE`表示已判定可以下架但索引侧尚未执行，仍计一条差异，直到下架落地。`ORPHAN_WAITING`同样计差异，但原因只记等待，不记延迟或内容差异。

同一批补发重试按批次键（参数`batch_id`，缺省为运行号）与（文档，结论编号）去重：证据不变的结论只留一份，已被新证据取代的旧结论不再出现在当前结论中，但保留在`/api/conclusions/history`并可从`/api/runs/<id>/records`追回原始记录。`/api/runs/<id>/conclusions`返回该次运行载荷内的结论快照，重试不会改写历史批次的封存证据。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
